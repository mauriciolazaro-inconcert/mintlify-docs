## Propósito

El módulo de credenciales permite almacenar datos sensibles, como API keys, tokens o contraseñas, y recuperarlos desde el código de una herramienta en tiempo de ejecución.

<Callout type="info">
  Usa credenciales para evitar hardcodear secretos directamente en el código de una herramienta. Las credenciales se recuperan ya descifradas y listas para usar.
</Callout>

## Crear una credencial desde la interfaz

<Steps>
  <Step title="Abre Credenciales">Desde la navegación de Inagent, entra en **Credenciales** y selecciona **Crear credencial**.</Step>
  <Step title="Elige el tipo">Selecciona **API Key**, **Bearer Token**, **OAuth2** o **Variables de configuración** según lo indicado por la integración.</Step>
  <Step title="Completa los campos">Asigna un nombre reconocible y pega los valores en su campo correspondiente. Los campos secretos aparecen ocultos después de guardar.</Step>
  <Step title="Guarda y selecciona">Guarda la credencial y vuelve a la herramienta para elegirla en su selector.</Step>
</Steps>

<CredentialCreationFlow />

| Tipo | Úsalo para | Campos habituales |
| --- | --- | --- |
| **API Key** | Claves de servicios como Airtable o Supabase. | Nombre y API Key. |
| **Bearer Token** | Tokens personales enviados como Bearer, como Calendly. | Nombre y Token. |
| **OAuth2** | Flujos de credenciales de cliente, como Salesforce o Shopify. | Client ID, Client Secret y, cuando corresponda, Token URL. |
| **Variables de configuración** | Identificadores y valores no secretos asociados a una conexión. | Pares Clave/Valor. |

<Callout type="warning">
  No guardes tokens ni secretos en Variables de configuración, nombres, descripciones o capturas. Usa siempre el campo secreto del tipo de credencial correspondiente.
</Callout>

## Métodos disponibles

`controller.credentials` expone dos métodos para recuperar credenciales:

<CredentialsIntellisense />

Ambos métodos buscan únicamente credenciales **activas del tenant de la sesión**. Devuelven `undefined` si la credencial no existe o no está activa. Los valores de `privateAttributes` se entregan ya descifrados.

<Callout type="warning">
  No devuelvas el objeto credencial como resultado de la herramienta ni lo registres en logs. Usa los secretos únicamente para autenticar la solicitud y devuelve solo los datos que necesita el agente.
</Callout>

### `getByName(name: string)`

Recupera una credencial por su nombre. Es el método habitual cuando el código debe usar una credencial conocida por su identificador funcional.

```javascript
const credential = await controller.credentials.getByName("nombre_credencial");
```

### `getById(id: string)`

Recupera una credencial por su identificador único (UUID).

```javascript
const credential = await controller.credentials.getById("uuid-de-la-credencial");
```

## Estructura de una credencial

Una vez recuperada, la credencial expone las siguientes propiedades:

<CredentialPropertiesIntellisense />

| Propiedad | Descripción |
| --- | --- |
| `id` | Identificador único de la credencial. |
| `name` | Nombre de la credencial. |
| `description` | Descripción opcional. |
| `type` | Tipo de credencial. Determina el esquema de atributos. |
| `active` | Indica si la credencial está activa. |
| `TenantId` | Tenant al que pertenece la credencial. |
| `createdAt` | Fecha de creación. |
| `createdBy` | Usuario que creó la credencial. |
| `publicAttributes` | Atributos no sensibles, como el nombre de un header o una URL base. |
| `publicAttributesSchema` | Esquema JSON de los atributos públicos. |
| `privateAttributes` | Atributos sensibles descifrados, como una API key, token o contraseña. |
| `privateAttributesSchema` | Esquema JSON de los atributos privados. |

### `publicAttributes` vs `privateAttributes`

- **`publicAttributes`**: datos no sensibles asociados a la credencial. Por ejemplo, en una credencial de tipo API key, aquí puede guardarse el nombre del header HTTP donde debe enviarse la clave, como `X-Api-Key` o `Authorization`.
- **`privateAttributes`**: datos sensibles almacenados cifrados y entregados ya descifrados en tiempo de ejecución. Aquí puede guardarse la API key, el token o la contraseña.

## Campos por tipo de credencial

El valor de `type` determina qué campos debes leer. Los nombres de las propiedades distinguen mayúsculas y minúsculas: por ejemplo, usa `headerName` y `apiKey`.

| Tipo | Valor de `type` | Campos en `publicAttributes` | Campos en `privateAttributes` |
| --- | --- | --- | --- |
| **API Key** | `apikey` | `headerName` | `apiKey` |
| **Bearer** | `bearer` | — | `token` |
| **Basic Auth** | `basic` | `username` | `password` |
| **Valores (Variables de configuración)** | `values` | `variables`: array de objetos con `key` y `value`. | — |
| **OAuth 2.0** | `oauth2` | `clientId`, `scopes`, `tokenUrl`, `authUrl` | `accessToken`, `refreshToken`, `clientSecret` |

## Validar antes de usar

Comprueba que la credencial existe y que contiene los campos que necesitas. Una credencial puede estar activa y tener valores sin completar.

```javascript
const credential = await controller.credentials.getByName("mi_api_externa");

if (!credential) {
  return {
    ok: false,
    error: "La credencial mi_api_externa no existe o no está activa."
  };
}

if (!credential.privateAttributes?.apiKey) {
  return { ok: false, error: "Falta apiKey en mi_api_externa." };
}

const apiKey = credential.privateAttributes.apiKey;
// Usa apiKey para autenticar la solicitud, sin devolverla ni registrarla.
```

La comprobación de `privateAttributes` evita acceder a un campo de un objeto que podría no estar definido. Aplica la misma validación a `publicAttributes` cuando necesites un dato público.

## Usar cada tipo desde código

Los siguientes fragmentos se ejecutan dentro de la función asíncrona de una [herramienta de código](/tools/code), donde está disponible `controller`. Las URLs, los nombres de credenciales y los campos de respuesta son ilustrativos: adáptalos a tu integración.

### API Key

Lee el nombre de la cabecera en `publicAttributes.headerName` y la clave en `privateAttributes.apiKey`.

```javascript
const credential = await controller.credentials.getByName("servicio_apikey");
const headerName = credential?.publicAttributes?.headerName;
const apiKey = credential?.privateAttributes?.apiKey;

if (!headerName || !apiKey) {
  return {
    ok: false,
    error: "Revisa la credencial servicio_apikey: faltan headerName o apiKey."
  };
}

const response = await fetch("https://api.example.com/registros", {
  headers: {
    [headerName]: apiKey,
    Accept: "application/json"
  }
});

if (!response.ok) {
  return { ok: false, error: "La API respondió " + response.status };
}

const data = await response.json();
return { ok: true, registros: (data.items || []).length };
```

<Callout type="info">
  `headerName` define el nombre de la cabecera, pero no el formato del valor. Este ejemplo envía la clave directamente, como requiere una cabecera `x-api-key`. Si tu API exige `Authorization: Bearer ...`, configura `Authorization` como nombre y envía `"Bearer " + apiKey` como valor.
</Callout>

### Bearer

El token se encuentra en `privateAttributes.token`. Envíalo en la cabecera `Authorization` con el prefijo `Bearer `.

```javascript
const credential = await controller.credentials.getByName("crm_bearer");
const token = credential?.privateAttributes?.token;

if (!token) {
  return { ok: false, error: "Revisa el token de la credencial crm_bearer." };
}

const response = await fetch("https://api.example.com/contactos", {
  headers: {
    Authorization: "Bearer " + token,
    Accept: "application/json"
  }
});

if (!response.ok) {
  return { ok: false, error: "El CRM respondió " + response.status };
}

const data = await response.json();
return { ok: true, contactos: (data.items || []).length };
```

### Basic Auth

El usuario está en `publicAttributes.username` y la contraseña en `privateAttributes.password`. Construye la cabecera `Authorization` codificando la cadena `usuario:contraseña` en Base64.

```javascript
const credential = await controller.credentials.getByName("erp_basic");
const username = credential?.publicAttributes?.username;
const password = credential?.privateAttributes?.password;

if (!username || !password) {
  return { ok: false, error: "Revisa el usuario y la contraseña de erp_basic." };
}

const basicAuth = "Basic " + btoa(username + ":" + password);
const response = await fetch("https://api.example.com/inventario", {
  headers: {
    Authorization: basicAuth,
    Accept: "application/json"
  }
});

if (!response.ok) {
  return { ok: false, error: "El ERP respondió " + response.status };
}

const data = await response.json();
return { ok: true, productos: (data.items || []).length };
```

`btoa` solo admite caracteres Latin-1. Para credenciales con caracteres fuera de ese rango, sustituye la construcción de `basicAuth` por la codificación UTF-8 con `CryptoJS`:

```javascript
const basicAuth = "Basic " + CryptoJS.enc.Base64.stringify(
  CryptoJS.enc.Utf8.parse(username + ":" + password)
);
```

### Valores (Variables de configuración)

Los pares clave-valor se encuentran en `publicAttributes.variables` como un array de objetos con la forma `{ key: string, value: string }`. Convierte el array en un objeto para acceder a cada valor por su clave.

Este tipo sirve para configuración no sensible, como identificadores, URLs o nombres de tablas. No aporta autenticación por sí mismo.

```javascript
const credential = await controller.credentials.getByName("servicio_config");
const entries = credential?.publicAttributes?.variables;

if (!Array.isArray(entries)) {
  return { ok: false, error: "Revisa las variables de servicio_config." };
}

const variables = Object.fromEntries(
  entries.map(({ key, value }) => [key, value])
);

if (!variables.BASE_ID || !variables.TABLE_ID) {
  return { ok: false, error: "Faltan BASE_ID o TABLE_ID en servicio_config." };
}

let url = "https://api.example.com/bases/" +
  encodeURIComponent(variables.BASE_ID) + "/tables/" +
  encodeURIComponent(variables.TABLE_ID);

// VIEW_NAME es opcional en este ejemplo.
if (variables.VIEW_NAME) {
  url += "?" + new URLSearchParams({ view: variables.VIEW_NAME }).toString();
}

// Usa url al realizar la solicitud con la credencial de autenticación.
```

<Callout type="warning">
  Estos valores están en `publicAttributes`. Guarda tokens, claves y contraseñas en los campos privados del tipo de credencial correspondiente.
</Callout>

### OAuth 2.0

Para realizar la solicitud, usa `privateAttributes.accessToken`. Los demás campos describen la aplicación y la autorización OAuth:

| Campo | Ruta | Uso |
| --- | --- | --- |
| Client ID | `publicAttributes.clientId` | Identificador de la aplicación OAuth. |
| Scopes | `publicAttributes.scopes` | Permisos autorizados. |
| Token URL | `publicAttributes.tokenUrl` | URL del endpoint de tokens. |
| Auth URL | `publicAttributes.authUrl` | URL de autorización. |
| Access Token | `privateAttributes.accessToken` | Token de acceso para la solicitud. |
| Refresh Token | `privateAttributes.refreshToken` | Token de renovación. |
| Client Secret | `privateAttributes.clientSecret` | Secreto de la aplicación OAuth. |

```javascript
const credential = await controller.credentials.getByName("servicio_oauth");
const accessToken = credential?.privateAttributes?.accessToken;

if (!accessToken) {
  return { ok: false, error: "Falta el token de acceso en servicio_oauth." };
}

const response = await fetch("https://api.example.com/registros", {
  headers: {
    Authorization: "Bearer " + accessToken,
    Accept: "application/json"
  }
});

if (response.status === 401) {
  return {
    ok: false,
    error: "La API rechazó el token. Revisa la autorización de servicio_oauth."
  };
}
if (!response.ok) {
  return { ok: false, error: "La API respondió " + response.status };
}

const data = await response.json();
return { ok: true, registros: (data.items || []).length };
```

<Callout type="info">
  Inagent gestiona la renovación del token OAuth. Usa el `accessToken` recuperado sin implementar el ciclo de renovación en la herramienta. Si la API responde con un `401`, revisa la credencial: puede ser necesario volver a autorizarla desde el módulo de credenciales.
</Callout>

## Combinar autenticación y configuración

Puedes usar una credencial de **API Key** para autenticar la solicitud y otra de **Valores** para guardar los identificadores de la integración. Así puedes cambiar la configuración sin escribir esos valores directamente en el código.

En este ejemplo, `servicio_apikey` contiene `headerName` y `apiKey`, mientras que `servicio_config` contiene las variables `BASE_ID` y `TABLE_ID`. La API ilustrativa espera la clave sin prefijo en la cabecera configurada.

```javascript
const auth = await controller.credentials.getByName("servicio_apikey");
const headerName = auth?.publicAttributes?.headerName;
const apiKey = auth?.privateAttributes?.apiKey;

if (!headerName || !apiKey) {
  return { ok: false, error: "Revisa headerName y apiKey en servicio_apikey." };
}

const config = await controller.credentials.getByName("servicio_config");
const entries = config?.publicAttributes?.variables;

if (!Array.isArray(entries)) {
  return { ok: false, error: "Revisa las variables de servicio_config." };
}

const variables = Object.fromEntries(
  entries.map(({ key, value }) => [key, value])
);

if (!variables.BASE_ID || !variables.TABLE_ID) {
  return { ok: false, error: "Faltan BASE_ID o TABLE_ID en servicio_config." };
}

const url = "https://api.example.com/bases/" +
  encodeURIComponent(variables.BASE_ID) + "/tables/" +
  encodeURIComponent(variables.TABLE_ID);

const response = await fetch(url, {
  headers: {
    [headerName]: apiKey,
    Accept: "application/json"
  }
});

if (!response.ok) {
  return { ok: false, error: "La API respondió " + response.status };
}

const data = await response.json();
return { ok: true, registros: (data.items || []).length };
```

El código de cada herramienta es autocontenido. Si repites la recuperación y validación, copia estas funciones dentro de la función asíncrona de cada herramienta que las necesite, donde tengan acceso a `controller`.

```javascript
async function getCredential(name, privateField) {
  const credential = await controller.credentials.getByName(name);

  if (!credential) {
    throw new Error("La credencial " + name + " no existe o no está activa.");
  }
  if (privateField && !credential.privateAttributes?.[privateField]) {
    throw new Error("Falta " + privateField + " en la credencial " + name + ".");
  }

  return credential;
}

function parseVariables(credential) {
  const entries = credential?.publicAttributes?.variables;
  if (!Array.isArray(entries)) return {};
  return Object.fromEntries(entries.map(({ key, value }) => [key, value]));
}
```

## Buenas prácticas

- Recupera credenciales por nombre cuando el código deba ser legible y estable.
- Valida la existencia de la credencial y cada campo requerido antes de usarlo.
- Mantén en `publicAttributes` solo datos que no sean sensibles; reserva **Valores** para configuración pública.
- Guarda los secretos en credenciales, en lugar de incluirlos en el código o en el JSON Schema de entradas de la herramienta.
- Devuelve solo los datos necesarios para la conversación. No incluyas la credencial, tokens, contraseñas ni cabeceras de autenticación.
- Para depurar, registra únicamente si se encontró la credencial, por ejemplo `console.log("Credencial encontrada:", !!credential)`.
- Prueba la herramienta en Playground antes de publicarla.
