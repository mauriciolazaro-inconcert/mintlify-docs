Conecta una Base y una tabla de Airtable para consultar registros y, si el caso de uso lo requiere, crearlos o modificarlos.

## Capacidades y requisitos

La aplicación puede leer, crear, actualizar y eliminar registros según los permisos que habilites en Inagent. Necesitas una cuenta de Airtable con acceso a la Base, una tabla preparada y permiso suficiente para las acciones seleccionadas.

Antes de empezar, obtén:

| Dato | Dónde encontrarlo |
| --- | --- |
| **Base ID** | Identificador de la Base; comienza por `app`. |
| **Table ID** | Identificador estable de la tabla; comienza por `tbl`. |
| **Personal Access Token** | Developer Hub de Airtable. Se muestra al generarlo. |

## Preparar Airtable

<Steps>
  <Step title="Abre la Base y la tabla">Crea o revisa los campos que utilizará el agente. Conserva sus nombres exactos.</Step>
  <Step title="Copia los identificadores">Obtén el **Base ID** y el **Table ID** desde Airtable. Usa el ID de tabla, no su nombre visible.</Step>
  <Step title="Crea el token">En el Developer Hub, crea un Personal Access Token dedicado y añade la Base como único recurso de acceso.</Step>
  <Step title="Selecciona los scopes">Añade `data.records:read` y `schema.bases:read`. Incluye `data.records:write` solo si habilitarás creación, actualización o eliminación.</Step>
</Steps>

El token nunca puede hacer más de lo permitido al usuario que lo creó y solo alcanza los recursos seleccionados. Consulta [Crear Personal Access Tokens en Airtable](https://support.airtable.com/articles/9934989703-creating-personal-access-tokens) y la [introducción a la Web API](https://support.airtable.com/articles/6292134965-getting-started-with-airtable-s-web-api).

## Crear las credenciales en Inagent

Necesitas dos credenciales:

1. **Variables de configuración** con `BASE_ID` y `TABLE_ID`.
2. **API Key** con el Personal Access Token. Usa un nombre reconocible y no pegues el token en descripciones ni campos de variables.

Si necesitas revisar el alta de cada tipo, consulta [Credenciales](../credentials).

## Añadir Airtable desde el Market

<Steps>
  <Step title="Abre el Market">En el agente, selecciona **Crear herramienta → Market → Airtable**.</Step>
  <Step title="Asocia las credenciales">Selecciona la credencial de Variables de configuración y la credencial API Key creadas anteriormente.</Step>
  <Step title="Define los permisos">Empieza con **Lectura**. Activa inserción o actualización solo si el agente debe escribir; deja eliminación desactivada inicialmente.</Step>
  <Step title="Guarda">Revisa la Base, la tabla y el alcance antes de guardar la herramienta.</Step>
</Steps>

## Instrucciones recomendadas para el guion del AV

Añade estas instrucciones al guion del Agente Virtual y adáptalas al caso de uso. El texto no sustituye los permisos configurados en la herramienta: si una operación está deshabilitada, el agente no podrá ejecutarla.

```text
Tienes acceso a una herramienta de Airtable.

REGLAS:
- Respeta las operaciones habilitadas en la configuración de la herramienta.
- obtener_schema está siempre disponible, aunque los permisos sobre los datos estén desactivados.
- No asumas nombres de tablas, campos, tipos ni opciones.
- Usa obtener_schema cuando no conozcas la estructura actual de la tabla.
- Usa exactamente los nombres de campo devueltos por el esquema.
- Para campos singleSelect o multipleSelects, usa únicamente las opciones devueltas por el esquema.
- Para crear o actualizar un registro, envía fields como un objeto con los nombres de campo reales de Airtable.
- Para obtener, actualizar o eliminar un registro, usa el record_id interno devuelto por Airtable.
- No confundas record_id, con formato recXXXX, con un identificador funcional guardado en una columna.
- buscar realiza una coincidencia exacta sin distinguir entre mayúsculas y minúsculas, y está pensado para campos de texto.
- Antes de eliminar, identifica el registro y pide al usuario confirmación explícita sobre qué registro concreto debe borrarse.
- No inventes nombres de campo, opciones, identificadores ni datos.
- Si la herramienta devuelve status "error", explica el problema y corrige los argumentos antes de reintentar.
```

## Comprobación final

1. Solicita una lectura limitada de una tabla con datos de prueba.
2. Confirma que los campos corresponden a la tabla elegida.
3. Si habilitaste escritura, crea o actualiza un registro de prueba y revísalo en Airtable.
4. Verifica que una operación deshabilitada sea rechazada.

## Errores frecuentes

<AccordionGroup>
  <Accordion title="La Base o la tabla no se encuentran">Comprueba que los IDs comiencen por `app` y `tbl`, y que la Base figure entre los recursos del token.</Accordion>
  <Accordion title="Falta acceso al esquema">Añade `schema.bases:read`; es necesario para que la aplicación reconozca los campos de la tabla.</Accordion>
  <Accordion title="Una escritura devuelve acceso denegado">Revisa `data.records:write`, los permisos del usuario de Airtable y que la operación esté habilitada en Inagent.</Accordion>
  <Accordion title="El token dejó de funcionar">Comprueba que no se haya regenerado, eliminado o modificado. Si se regeneró, actualiza la credencial en Inagent.</Accordion>
</AccordionGroup>
